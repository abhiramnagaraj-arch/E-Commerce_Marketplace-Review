## 1️⃣ MIGRATION FILE 1: `create_categories.rb`

### Complete Code
```ruby
# db/migrate/20260728202959_create_categories.rb
class CreateCategories < ActiveRecord::Migration[8.1]
  def change
    create_table :categories do |t|
      t.string :name
      t.text :description

      t.timestamps
    end
  end
end
```

---

### 📋 Complete File Explanation (10-Point Checklist)
1. **Why this file exists:** It is a database migration script that instructs PostgreSQL to create the `categories` table.
2. **Why we need it:** We need a place to store product categories (e.g., "Laptops", "Smartphones", "Accessories") in our database in a structured way.
3. **What every function does:** The `change` method defines what changes should be applied to the database schema when we run `rails db:migrate`.
4. **What every line is doing:**
   - `class CreateCategories < ActiveRecord::Migration[8.1]`: Declares a migration class inheriting from Rails' built-in database migration engine (version 8.1).
   - `def change`: Defines the migration action.
   - `create_table :categories do |t|`: Opens a block instructing ActiveRecord to create a table named `categories`.
   - `t.string :name`: Creates a `name` column with string datatype (SQL `VARCHAR`).
   - `t.text :description`: Creates a `description` column with text datatype (SQL `TEXT`).
   - `t.timestamps`: Automatically generates two columns: `created_at` and `updated_at` (SQL `TIMESTAMP WITHOUT TIME ZONE`).
5. **Which MVC layer it belongs to:** **Model / Data Layer** (specifically Database Migrations).
6. **Which database table it uses:** Creates and manages the `categories` table.
7. **Which routes call this file:** Routes do not call migrations directly; migrations are executed via the command line (`rails db:migrate`).
8. **Which views use this controller:** Not applicable (this is a migration, not a controller).
9. **Which model is connected:** Connected to `app/models/category.rb`.
10. **What will happen if I remove this code:** If removed before migrating, PostgreSQL will not create the `categories` table, and saving any category in Rails will throw a `PG::UndefinedTable: ERROR: relation "categories" does not exist` error.

---

### 🔍 Column & Datatype Breakdown
- `id` *(Auto-created by Rails)*: Primary key (`BIGINT GENERATED BY DEFAULT AS IDENTITY`). Used to uniquely identify each category.
- `name` (`string`): Chosen because category names are short titles (under 255 characters).
- `description` (`text`): Chosen because descriptions can be long paragraphs of unlimited length.
- `created_at` / `updated_at` (`datetime`): Auto-managed by Rails to track record creation and modification timestamps.

### 🐘 Equivalent PostgreSQL `CREATE TABLE` Statement
When you run `rails db:migrate`, ActiveRecord converts Ruby into the following PostgreSQL SQL command:

```sql
CREATE TABLE categories (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(255),
  description TEXT,
  created_at TIMESTAMP WITHOUT TIME ZONE NOT NULL,
  updated_at TIMESTAMP WITHOUT TIME ZONE NOT NULL
);
```

## 2️⃣ MIGRATION FILE 2: `create_products.rb`

### Complete Code
```ruby
# db/migrate/20260728203010_create_products.rb
class CreateProducts < ActiveRecord::Migration[8.1]
  def change
    create_table :products do |t|
      t.string :title
      t.text :description
      t.decimal :price, precision: 10, scale: 2
      t.integer :stock, default: 0
      t.references :category, null: false, foreign_key: true

      t.timestamps
    end
  end
end
```

---

### 📋 Complete File Explanation (10-Point Checklist)
1. **Why this file exists:** It creates the `products` table in the PostgreSQL database.
2. **Why we need it:** We need a database table to store all products available in our E-Commerce store, including their prices, stock quantities, and which category they belong to.
3. **What every function does:** The `change` method defines the table schema and foreign key constraints for products.
4. **What every line is doing:**
   - `create_table :products do |t|`: Instructs ActiveRecord to create the `products` table.
   - `t.string :title`: Creates a string column for the product name/title.
   - `t.text :description`: Creates a text column for detailed product specifications.
   - `t.decimal :price, precision: 10, scale: 2`: Creates a decimal column that can store numbers up to 10 digits total, with 2 decimal places (e.g., `99999999.99`), which is standard for currency.
   - `t.integer :stock, default: 0`: Creates an integer column for inventory count, defaulting to `0` so products don't start with `NULL` stock.
   - `t.references :category, null: false, foreign_key: true`: Creates a `category_id` integer column, adds a database index on it, and sets a PostgreSQL foreign key constraint pointing to `categories(id)`.
   - `t.timestamps`: Adds `created_at` and `updated_at` columns.
5. **Which MVC layer it belongs to:** **Model / Data Layer**.
6. **Which database table it uses:** `products` table.
7. **Which routes call this file:** Command-line migration only (`rails db:migrate`).
8. **Which views use this controller:** Not applicable.
9. **Which model is connected:** Connected to `app/models/product.rb`.
10. **What will happen if I remove this code:** Without this table, products cannot be stored, and queries on `Product` will fail immediately.

---

### 🔍 Column & Datatype Breakdown
- `title` (`string`): Chosen for short product titles (SQL `VARCHAR`).
- `price` (`decimal`): Chosen instead of `float` because floating-point numbers have rounding errors in computers (e.g., `0.1 + 0.2 = 0.30000000000000004`). In financial and E-Commerce apps, **always use `decimal`** for money.
- `stock` (`integer`): Chosen because inventory is counted in whole numbers.
- `category_id` (`bigint`): Chosen as a foreign key to link a product to its parent category.

### 🐘 Equivalent PostgreSQL `CREATE TABLE` Statement
```sql
CREATE TABLE products (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title VARCHAR(255),
  description TEXT,
  price DECIMAL(10, 2),
  stock INTEGER DEFAULT 0,
  category_id BIGINT NOT NULL,
  created_at TIMESTAMP WITHOUT TIME ZONE NOT NULL,
  updated_at TIMESTAMP WITHOUT TIME ZONE NOT NULL,
  CONSTRAINT fk_rails_products_categories FOREIGN KEY (category_id) REFERENCES categories (id)
);

CREATE INDEX index_products_on_category_id ON products (category_id);
```

## 3️⃣ MODEL FILE 1: `app/models/category.rb`

### Complete Code
```ruby
# app/models/category.rb
class Category < ApplicationRecord
  has_many :products, dependent: :destroy

  validates :name, presence: true, uniqueness: true
end
```

---

### 📋 Complete File Explanation (10-Point Checklist)
1. **Why this file exists:** It defines the `Category` ActiveRecord model class in Ruby.
2. **Why we need it:** It allows us to interact with the `categories` table using object-oriented Ruby code instead of raw SQL queries.
3. **What every function does:** This file declares associations and validation rules rather than explicit methods; ActiveRecord automatically generates methods like `.products`, `.save`, and `.create`.
4. **What every line is doing:**
   - `class Category < ApplicationRecord`: Defines the `Category` class inheriting from `ApplicationRecord` (which inherits from `ActiveRecord::Base`).
   - `has_many :products, dependent: :destroy`: Tells Rails that one category can contain multiple products. If a category is deleted from the database, `:destroy` automatically deletes all products in that category so we don't have orphaned records.
   - `validates :name, presence: true, uniqueness: true`: Ensures that a category cannot be saved without a `name`, and no two categories can have the exact same name.
5. **Which MVC layer it belongs to:** **Model Layer (M in MVC)**.
6. **Which database table it uses:** `categories`.
7. **Which routes call this file:** Called by `CategoriesController` and `ProductsController` routes.
8. **Which views use this controller:** Used in `app/views/categories/index.html.erb`, `show.html.erb`, etc.
9. **Which model is connected:** Connected to `Product` via `has_many :products`.
10. **What will happen if I remove this code:** We would lose all validation logic and `.products` associations, causing errors whenever we try to fetch products belonging to a category.

---

### 🔗 Model Association Details (`has_many`)
- **Association:** `has_many :products`
- **Why required:** In an E-Commerce app, products are grouped by category. This association lets you write `category.products` in Ruby instead of writing `Product.where(category_id: category.id)`.
- **Database Columns:** Uses the primary key `categories.id` and connects to the foreign key `products.category_id`.

## 4️⃣ MODEL FILE 2: `app/models/product.rb`

### Complete Code

```ruby
# app/models/product.rb
class Product < ApplicationRecord
  belongs_to :category

  validates :title, presence: true
  validates :price, presence: true, numericality: { greater_than_or_equal_to: 0 }
  validates :stock, presence: true, numericality: { only_integer: true, greater_than_or_equal_to: 0 }
end
```

---

### 📋 Complete File Explanation (10-Point Checklist)
1. **Why this file exists:** It defines the `Product` ActiveRecord model class.
2. **Why we need it:** To represent individual products in our application and enforce rules on product data before saving to PostgreSQL.
3. **What every function does:** Sets up the `belongs_to` association with `Category` and validates data integrity for titles, prices, and stock counts.
4. **What every line is doing:**
   - `class Product < ApplicationRecord`: Defines the `Product` model class.
   - `belongs_to :category`: Declares that every product must belong to a single category. Rails automatically requires `category_id` to be present.
   - `validates :title, presence: true`: Rejects any attempt to save a product with an empty or nil title.
   - `validates :price, presence: true, numericality: { greater_than_or_equal_to: 0 }`: Ensures price is present and cannot be a negative number.
   - `validates :stock, presence: true, numericality: { only_integer: true, greater_than_or_equal_to: 0 }`: Ensures stock is a non-negative whole integer (you cannot have `-5` or `2.5` items in stock).
5. **Which MVC layer it belongs to:** **Model Layer (M in MVC)**.
6. **Which database table it uses:** `products`.
7. **Which routes call this file:** Called by routes handled by `ProductsController` and `CartController`.
8. **Which views use this controller:** Used in `app/views/products/index.html.erb`, `show.html.erb`, `new.html.erb`, etc.
9. **Which model is connected:** Connected to `Category` (`belongs_to :category`).
10. **What will happen if I remove this code:** Products could be saved with negative prices, missing titles, or invalid category references, corrupting the database.

---

### 🔗 Model Association Details (`belongs_to`)
- **Association:** `belongs_to :category`
- **Why required:** Links each product row to its parent category. Allows you to call `product.category.name` directly in your ERB views.
- **Database Columns:** Requires the `category_id` column on the `products` table.

## 5️⃣ HOW ACTIVERECORD CONVERTS RUBY INTO SQL

When you write Ruby code in your controllers or console, ActiveRecord translates it into SQL commands sent to PostgreSQL:

### 1. SELECT (Reading Data)
```ruby
# Ruby Code
@products = Product.where(category_id: 1).order(price: :asc)
```
**Equivalent SQL:**
```sql
SELECT "products".* FROM "products" 
WHERE "products"."category_id" = 1 
ORDER BY "products"."price" ASC;
```

### 2. INSERT (Creating Data)
```ruby
# Ruby Code
Category.create(name: "Laptops", description: "All modern laptops")
```
**Equivalent SQL:**
```sql
INSERT INTO "categories" ("name", "description", "created_at", "updated_at") 
VALUES ('Laptops', 'All modern laptops', '2026-07-28 20:31:00', '2026-07-28 20:31:00') 
RETURNING "id";
```

### 3. UPDATE (Modifying Data)
```ruby
# Ruby Code
product = Product.find(1)
product.update(price: 499.99)
```
**Equivalent SQL:**
```sql
SELECT "products".* FROM "products" WHERE "products"."id" = 1 LIMIT 1;
UPDATE "products" SET "price" = 499.99, "updated_at" = '2026-07-28 20:32:00' 
WHERE "products"."id" = 1;
```

### 4. DELETE (Removing Data)
```ruby
# Ruby Code
Product.find(1).destroy
```
**Equivalent SQL:**
```sql
DELETE FROM "products" WHERE "products"."id" = 1;
```

- **What to modify:**
```diff
- has_many :products, dependent: :destroy
+ has_many :products, dependent: :restrict_with_error
```
*Explanation:* With `:restrict_with_error`, Rails will block deletion and show an error message if any product is still linked to that category.
